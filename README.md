# 夜灯 · 私人影视库

一台 Windows 电脑运行的局域网影视库。前台可免登录浏览、播放和下载；访客可以注册账户收藏影片，管理后台需要管理员登录。Nuxt 4 单进程同时提供页面和 API，本地 SQLite 保存目录索引与元数据，原视频和海报留在独立的媒体目录。没有内置影片、联网刮削、转码或公网入口。

## 1. 在 Windows 启动

安装 **Node.js 24 LTS（24.15 或更新的 24.x）**；SQLite 使用 `node:sqlite`，不需要 Python、C++ 编译工具、SQLite 服务或 FFmpeg。以下命令在项目根目录的 PowerShell 中执行：

```powershell
node --version
npm install --global pnpm@11.28.5
pnpm install --frozen-lockfile
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
New-Item -ItemType Directory -Path media -Force
pnpm admin:create --username admin
pnpm build
pnpm start
```

- `admin:create` 在终端隐藏输入，密码**至少 6 位**。对同一数据库再运行该命令会重置唯一管理员并使旧会话失效；不会修改影片数据。不要把密码放进命令行、`.env` 或仓库。
- 浏览器打开 `http://127.0.0.1:3000`，管理入口是 `/admin`。直接复制到 `media` 或从后台上传影片。默认启动只绑定回环地址。开发命令 `pnpm dev` 也只绑定回环，不能代替内网部署。
- 在 `.env` 里可设置 `NUXT_LIBRARY_DB_PATH`（服务主机的持久**本地**磁盘）和 `NUXT_LIBRARY_MEDIA_ROOT`（媒体根）。相对路径均以启动命令所在的项目根为基准；Windows 绝对路径建议单引号，例如 `NUXT_LIBRARY_MEDIA_ROOT='D:\影视馆藏'`。自己建立媒体目录并设置权限，应用不会把访问失败当成一个空库。

### 双击管理网站

首次安装依赖并执行 `pnpm build` 后，双击项目根目录的 `影视库管理.cmd`，按 **1 启动、2 停止、3 重启、4 查看状态、0 退出**。启动与重启会自动打开浏览器；管理窗口关闭后，网站仍在后台运行。

- 脚本优先使用 PATH 中符合版本要求的 Node.js；没有时会尝试当前用户的 DeepSeek Harness 自带 Node.js。也可以用环境变量 `NIGHT_LIBRARY_NODE` 指定 Node 可执行文件。
- 监听地址、端口、媒体目录和数据库沿用现有环境变量与 `.env`；默认仍为 `127.0.0.1:3000`，不会自动开放局域网或修改 Windows 防火墙。修改监听配置后按 3 重启。局域网设置请看下一节。
- 脚本只停止自己启动且身份核验通过的进程。若端口被其他程序或手动启动的网站占用，会提示先关闭旧实例，不会强行结束其他程序。运行状态记录和输出/错误日志保存在 `.data`；网站数据不会被删除。
- **停止是直接结束进程**，会中断正在播放或上传的文件；请先等上传完成。中断上传留下的暂存文件会按入库规则在后续扫描中清理。重启会先确认旧进程退出再启动。
- 也可在命令行执行 `.\影视库管理.cmd start`、`.\影视库管理.cmd stop`、`.\影视库管理.cmd restart` 或 `.\影视库管理.cmd status`；不希望自动打开浏览器时，在命令后加 `-NoBrowser`。

## 2. 用户与管理员

两种账号互相独立，使用不同的登录 Cookie，普通用户无法进入管理后台或调用管理 API。

- **管理员**：只有一个，用 `pnpm admin:create --username admin` 创建或重置，密码至少 6 位。管理入口是 `/admin`，登录后可上传、扫描、整理和批量发布。
- **普通用户**：在 `/user` 自行注册，密码同样至少 6 位，用户名不可重复。登录后可以收藏影片、在 `/my-list` 查看和取消收藏。收藏按影片记录，源文件被移除时条目仍保留，但只会显示当前仍可浏览的影片。
- 管理后台分为「文件清单」「上传与扫描」「批量处理」三个标签页，一次只显示一栏，避免页面过长。

## 3. 开放给指定的局域网

只建议在受信任的家庭或办公私网使用。局域网 HTTP 未加密，不要在来宾 Wi-Fi 使用同一个管理员密码。只公开拥有存放及分发权利的资源。

1. `Get-NetIPConfiguration` 和 `Get-NetIPAddress -AddressFamily IPv4` 查到想绑定的网卡地址和前缀长度，为该主机做 DHCP 保留（地址改变时更新配置）。假设实际是 `192.168.1.20/24`，编辑 `.env`：

   ```dotenv
   NITRO_HOST=192.168.1.20
   NITRO_PORT=3000
   NUXT_LIBRARY_ALLOWED_ORIGINS=http://192.168.1.20:3000
   NUXT_LIBRARY_SECURE_COOKIES=false
   ```

   启动脚本只接受 `127.0.0.1` 或一个私有 IPv4，不使用全接口绑定。来源白名单填实际地址，写入时还必须与浏览器所访问的源完全相同。服务直连，不信任转发的 Host 和协议。不要配置端口转发、公网代理或隧道。
2. 在**已确认受信任且标记为“专用”**的 Windows 网络上，由管理员运行以下命令；地址和子网须换成**你的**值（不确定前缀时，先问网络管理员）。保持防火墙启用、默认阻止入站，检查并收窄以前为 Node/该端口开启的广域入站规则。不要通过 Windows 弹窗勾选放行公用网络。

   ```powershell
   $lanIp = '192.168.1.20'
   $lanSubnet = '192.168.1.0/24'
   New-NetFirewallRule -DisplayName '夜灯影视库 - 指定局域网' `
     -Direction Inbound -Action Allow -Profile Private -Protocol TCP `
     -LocalAddress $lanIp -LocalPort 3000 -RemoteAddress $lanSubnet
   ```

   只允许部分设备时，可将 `-RemoteAddress` 改为这些设备的固定 IP 列表。若使用多个网卡，确认规则的本地地址对应目标网卡。
3. 重新运行 `pnpm start`。同一网络中的手机或另一台电脑打开 `http://192.168.1.20:3000`（换实际地址）。若无法打开，先看主机本身能否用该地址访问，再检查防火墙、子网及 Wi-Fi 客户端隔离；不要绕过防火墙或开放公网来排障。

## 4. 入库规则与更换 NAS

- **上传**：后台选择 MP4 原文件，分块写到媒体根下的隐藏暂存目录。完整接收并检查 MP4 基本容器结构后才存入 `上传/`，同名不覆盖。不能完整传输的文件不入库；中断后移除暂存，异常退出留下的暂存由后续成功扫描清理（超过 24 小时）。一些 SMB 共享不支持硬链接，应用在这些共享上改用独占目标的复制，并在完成前将目标排除出扫描。海报支持 JPG、PNG、WebP，最多 8 MiB，可上传或输入根内相对路径（用 `/`，不可填 URL）。
- **复制**：命名示例 `电影/片名 (2024).mp4`、`剧名.S01E02.mp4`、`剧名 第02集.mp4`、`电视剧/剧名/第二季/第02集.mp4`。有明确季目录时采用目录的季号；有集号但无季号时默认第一季，季号冲突、多集、缺片名和重复位置会进入待整理。没有元数据时保留清晰的片名占位；可在后台补海报、简介、年份等。
- **按演员归类**：文件名写成 `演员-片名-发片标识`（例如 `杨幂-古剑奇谭-dx123.mp4`）时，第一段识别为演员、第二段是**真实片名**、最后一段是发片标识并会被丢弃。这样片名不会带上演员名字，演员自动进入「演员」页。只有严格用短横线连接的写法才会拆分，因此 `蜘蛛侠-英雄归来` 这类本身带连字符的片名不受影响；`剧名-S01E02` 也不会被当成演员。
- **剧集**：一个剧名下的多集共用一部「剧集」，前台详情页把每一集排成**横向紧凑的方块网格**（集号 + 集名，一格即一集，整格可点播放），只有多季时显示季标题；播放页也能选集。要让同一批文件归到一部剧，**文件名必须带集号**（`S01E02`、`s1e2`、`第02集`、`第2话` 均可），季号可写在文件名或上一级目录（`第二季`、`Season 2`）。只有数字的文件名（如 `02.mp4`）放在季目录里也能识别。文件名没有集号会被当成电影——这是识别规则，不是错误。
- **批量上传剧集**：后台「上传与扫描」支持一次选择多个 MP4，按选择顺序逐个流式上传并列出每个文件的结果，失败的不会中断其余文件。整套剧集只要命名带集号，一次选中上传即可自动归并到同一部剧。
- **扫描**：默认 15 秒扫描一次。新文件或变化文件至少要被观察两次，期间大小和修改时间不变、间隔达 `NUXT_LIBRARY_STABLE_MS`（默认 8 秒），并在读取时复查，才会入库。`NUXT_LIBRARY_SCAN_INTERVAL_MS=0` 时可先点击扫描、等稳定窗口再点击一次。对可能暂停得更久的拷贝，建议先拷到根外或用 `.part` 扩展名，完成后再移入或改名为 `.mp4`。隐藏目录、临时名称及链接/目录联接不会被扫描。后台可以查看歧义原因、显式替换占用的剧集位置（旧文件保留）、查看缺失状态。
- **缺失和掉线**：完整扫描发现原文件不在时保留条目和字段、禁用文件入口；恢复同一相对路径并通过扫描后更新可用状态。媒体根不可访问或扫描未完成时保留上次状态并报告失败；共享修复前，实际播放或下载仍会报不可用。
- **默认简介与封面**：后台「批量处理」里可填写一段默认简介并保存，之后批量发布和扫描自动入库的新影片都会用它；它只写入空白简介，不会覆盖你手工改过的内容。勾选「用视频第一帧作封面」时，浏览器会从视频里取一张画面、压成 JPEG 再上传为海报，因此服务主机**不需要安装 FFmpeg**。取帧失败只会退回片名占位封面，不影响入库。
- **片长自动识别**：入库时会读取 MP4 头里的 `moov/mvhd` 得到时长并换算成分钟，不需要手工填写，也不需要 FFmpeg。读不到时片长留空，仍可手动补充。
- **条目很多时**：后台「文件清单」默认一次渲染 40 条，可按片名/文件名搜索并「显示更多」；编辑面板的「归属条目」带筛选框，输入片名即可在大量条目中定位。
- **封面不会在扫描时自动生成**：扫描入库只登记影片，`poster_path` 留空，因为取帧要在浏览器里完成。这类影片在片库页面显示带片名的占位图，管理后台会在「批量处理」标签上显示待补数量，面板顶部给出提示并**默认选中所有缺封面的影片**，点一次执行即可用第一帧补齐；也可以点「只选缺封面的」重新选择。要完全无人值守地自动出图，才需要引入服务端 FFmpeg。
- **批量处理**：「补齐已有影片」给已发布但缺简介或封面的条目一次填好，按影片去重、默认只填空项，勾选覆盖才会改写；「发布待整理」把待整理文件按文件名推测的资料发布，无法判断片名或集号的会留在待整理并给出原因。每一项单独提交，个别失败不会回滚其他条目。
- **改用 NAS**：在同一个运行账户下确认 `Test-Path -LiteralPath '\\NAS\影视库'` 并可以在其中读写。停止服务，备份本地数据库和媒体，复制整个媒体根并保留相对布局（含 `_海报/`、`上传/` 等），保持 `NUXT_LIBRARY_DB_PATH` 不变。设置 `NUXT_LIBRARY_MEDIA_ROOT='\\NAS\影视库'`，重启并扫描确认。不要把 SQLite 放在共享盘。计划任务/Windows 服务也要以有共享和文件权限的账户运行，推荐用 UNC 而非仅在 Explorer 会话里可见的盘符。停止服务后备份 SQLite 所在目录；恢复时不要混用不同时间的数据库与 WAL。
- **播放格式**：推荐 MP4 + H.264（AVC）+ AAC，系统浏览器解码能力仍有差异。网站检查容器结构，不分析或转换编解码；不兼容时可下载原文件，建议用本地播放器。

## 5. 前台页面

前台是沉浸式观影界面，路由与作用如下：

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 轮播 Hero + 按评分、入库时间、类型自动生成的横向影片行 |
| `/browse?kind=movie` | 电影 | 导航里的「电影」，类型、地区、年份、评分筛选与排序，参数写进 URL |
| `/browse?kind=series` | 剧集 | 导航里的「剧集」，同样支持筛选；页面内不再切换电影/剧集 |
| `/actors` | 演员 | 片库中出现过的演员，按作品数排序 |
| `/actors/:name` | 演员作品 | 某位演员的全部电影与剧集 |
| `/search?q=` | 搜索 | 片名模糊匹配，显示结果数量，支持清空 |
| `/movie/:id` | 详情 | 背景剧照、海报、评分、片长、导演主演、剧集列表、相关推荐 |
| `/watch/:id` | 播放 | 原生播放器，支持快捷键、全屏、下载原文件 |
| `/my-list` | 我的收藏 | 需登录，展示收藏并可逐条移除 |
| `/user` | 账户 | 注册、登录、退出、修改密码 |

登录后首页会多出一行「继续观看」：播放页每 10 秒、暂停和离开页面时记录进度，回到首页可接着看；看完（97% 以上）会自动从这一行移除。播放器支持 0.75×–2× 倍速，选择会记住。

旧地址 `/title/:id` 和 `/favorites` 会 301 跳转到新路由。

- **导航**只有四项：首页、电影、剧集、我的收藏。电影与剧集的区别来自入库规则本身——有多集就是剧集，没有就是电影，因此页面内不再重复一个「全部/电影/剧集」的类型切换。
- 直接访问 `/browse`（不带 `kind`）仍会显示全部作品，便于从旧链接进入；筛选芯片不会改变当前所属的电影或剧集。

- 影片元数据（原名、类型、地区、评分、片长、导演、主演、背景图）在后台编辑面板里填写；类型和主演用「、」分隔。背景图与海报一样，填媒体根内的相对路径。- 首页与详情的横向剧照来自背景图（`?variant=backdrop`），没有背景图时退回海报，两者都没有则显示带片名的占位封面。
- 设计变量集中在 `app/assets/css/main.css`；组件在 `app/components/public/`。

## 6. 本地演示数据

想在不碰真实片库的情况下查看完整界面，可在项目根目录执行：

```powershell
python scripts/build-demo-posters.py   # 用缓存剧照合成带片名的海报（需要 Pillow）
pnpm demo:seed                          # 生成 .demo/ 下的独立数据库与媒体
pnpm build
$env:NUXT_LIBRARY_DB_PATH='.demo/library.sqlite'
$env:NUXT_LIBRARY_MEDIA_ROOT='.demo/media'
$env:NITRO_PORT='3100'; node .output/server/index.mjs
```

- 演示数据全部在 `.demo/` 与 `.demo-assets/`（均已被 `.gitignore` 忽略），不影响 `.data/library.sqlite` 和 `media/`。
- 片名与简介按每张剧照的实际画面撰写，海报由该剧照本地合成并直接在画面上排版片名，不使用、也不伪造任何第三方海报。
- 剧照来自 Unsplash 的免版权图片，下载后缓存在本地；视频是 `tests/fixtures/seek.mp4` 的彩条样片，只用于验证播放器，不会伪装成真实影片。
- `pnpm demo:review` 会在独立端口启动演示实例，按 1440×900、1920×1080、390×844 截图到 `.test-artifacts/visual/` 并检查控制台错误与横向溢出；`pnpm demo:flow` 会跑一遍筛选、搜索、播放、注册与收藏流程。

## 7. 开发和验收

- `app/` 负责视图与交互；`app/assets/css/main.css` 是唯一的设计变量来源；`shared/types/` 是展示/管理 DTO。
- `server/api/` 与 `server/http/` 校验边界、鉴权并处理 HTTP/Range；`server/services/` 协调扫描、上传与整理，扫描和上传共用 `indexMedia` 索引流程。
- `server/domain/` 保存命名和配置规则；`server/storage/` 集中文件系统安全、格式读取与暂存；`server/db/` 集中查询及按版本执行的 SQLite 迁移。迁移应在现有版本后追加，不改已部署的版本。

```powershell
pnpm test            # 规则、字节范围、数据库等单元测试
pnpm typecheck
pnpm build
pnpm test:http       # 启动独立的临时实例，验证生产 HTTP 和文件状态
pnpm test:browser    # 用本机 Edge 验证桌面、手机尺寸和原生 MP4 播放
pnpm test:poster     # 扫描入库的影片缺封面时，批量补齐第一帧封面
pnpm test:series     # 一次上传多集，验证归并为同一部剧并在详情页按集展示
pnpm test:episodes   # 多季多集时，分集仍是横向网格且不截断集名
pnpm test:progress   # 继续观看：保存进度、回到首页续播、看完自动清除
pnpm test:backdrop   # 后台设置背景图，以及搜索结果分页
pnpm test:batch4     # 海报 ETag/304、修改密码吊销会话、备份脚本
pnpm test:actors     # 演员-片名-标识 命名：片名干净、演员可点、筛选可用
pnpm test:scale      # 片长自动识别，以及大量条目下的搜索与分页
pnpm backup          # 用 VACUUM INTO 备份数据库到 backups/ 并统计媒体目录
pnpm test:frame      # 用本机 Edge 验证「取视频第一帧作封面」
```
